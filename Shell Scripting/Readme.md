One script, [`sysinfo.sh`](sysinfo.sh). It prints the date, hostname, user, disk usage and running
processes, asks where to save a report, creates that directory, and writes two files into it — one
assembled line by line, one a single dump.

```

├── demo-report/               what one run produced, kept as evidence
└── output/
    ├── full-run.txt           a complete run
    └── individual-commands.txt each command on its own, with its output
```

```bash
bash sysinfo.sh                  # prompts for a directory
bash sysinfo.sh -d myreports     # skip the prompt
bash sysinfo.sh -q               # print only the report path
echo mydir | bash sysinfo.sh     # unattended: the prompt reads from the pipe
```

## The commands, one at a time

Full capture in [`output/individual-commands.txt`](output/individual-commands.txt).

```
$ date
Fri Sep  4 23:12:28 IST 2026

$ hostname
Tarun

$ whoami
tarun

$ df -h
Filesystem            Size  Used Avail Use% Mounted on
C:/Program Files/Git  428G  232G  197G  55% /
D:                     49G   98M   49G   1% /d
```

`-h` on `df` is "human readable": `428G` instead of `459561959424`. The `Use%` column is the one
worth reading — `Avail` on its own does not tell you whether you are about to run out.

```
$ ps -ef | head -5
     UID     PID    PPID  TTY        STIME COMMAND
   tarun   10010   10003 ?        23:12:28 /usr/bin/tail
   tarun   10003       1 ?        23:12:28 /usr/bin/bash
```

`ps -ef`: `-e` is every process, `-f` is full format — UID, PID, PPID, start time, command. The
BSD spelling is `ps aux`, which shows `%CPU` and `%MEM` instead. `PPID` is the useful column when
you are trying to work out which process started the one misbehaving.

## `>` and `>>`

```
$ echo 'first line'  >  notes.txt
$ echo 'second line' >> notes.txt
$ cat notes.txt
first line
second line

$ echo 'this REPLACES everything' > notes.txt
$ cat notes.txt
this REPLACES everything
```

`>` truncates the file to zero and then writes. `>>` appends. One accidental `>` inside a loop and
the file ends up holding only the last iteration — silently, because neither form ever errors.

The script uses that deliberately: the report starts with exactly one `>` and every line after it
is `>>`. One reset at the top, appends below.

## Things that bit me

**`uptime` exits 0 and prints nothing.** The first version had:

```bash
UPTIME_LINE=$(uptime 2>/dev/null || echo "uptime unavailable")
```

which never produced the fallback, because Git Bash's `uptime` *succeeds* and returns an empty
string. Testing the exit status is not the same as testing the output:

```bash
UPTIME_LINE=$(uptime 2>/dev/null | sed 's/^ *//')
[ -z "$UPTIME_LINE" ] && UPTIME_LINE="(not reported by this shell)"
```

**The prompt has to survive being piped to.** `read -p` writes its prompt to stderr, so it still
appears when stdout is redirected, and it returns empty rather than hanging when stdin is a pipe.
Adding `TARGET_DIR=${TARGET_DIR:-$DEFAULT_DIR}` is what makes

```bash
echo mydir | bash sysinfo.sh          # answers the prompt
bash sysinfo.sh < /dev/null           # takes the default
```

both work. Without the default, an unattended run creates a directory called nothing at all, which
in practice means the files land in the current directory.

**`read -r`, not bare `read`.** Without `-r`, backslashes are treated as escapes, so typing a
Windows path such as `C:\reports\today` loses them and produces `C:reportstoday`.

**Quote every variable that holds a path.** `mkdir -p $TARGET_DIR` with an unquoted variable and a
directory name containing a space creates two directories. Everything in the script is
`"$TARGET_DIR"`, which is not decoration — this project lives under a path with a space in it.

**Counting with `wc -l` lies by one.** `ps -ef | wc -l` counts the header line as a process. The
count in the report is `tail -n +2 | grep -c .` so the number in "processes : 15" is actually the
number of processes.

## Platform notes

Run under Git Bash on Windows 11. Two things look different from a real Linux box:

- `df -h` shows `C:/Program Files/Git` as the root filesystem, because MSYS presents the Git
  installation as `/`. On Linux the same command lists `/dev/sda1` and friends.
- `ps -ef` only shows processes started from this shell environment — 15 of them here, against
  several hundred on a Linux machine. The columns are also a subset: no `%CPU` or `%MEM`.

Nothing in the script depends on either, so it produces the same report shape on Linux, with fuller
data.
